# 센트럴의 원격 에이전트 제거

## 요청과 대상

계정의 역할에 에이전트 원격 제거 권한이 있어야 하며, 제거할 에이전트의 현재 사이트에서 유효해야 한다. 단일 요청은 대상 에이전트 ID를 확인한다. 일괄 요청은 에이전트 목록, 그룹 또는 사이트를 지정한다. 미사용 대상을 정리할 때는 운영자가 직접 선택하거나 그룹을 만든다.

미리보기는 제거 가능한 현재 등록과 제외 사유를 보여준다. 유효 기간 안에 제거 가능 수를 확인하면 센트럴이 서명 토큰, 요청자, 선택 사이트, 현재 등록과 대상 집합을 다시 검증한다. 대상이나 제거 가능 여부가 달라지면 미리보기를 다시 만들어야 한다. 배치 결과는 대상별 상태를 저장한다.

## 실행과 취소

1. 센트럴은 각 현재 등록에 5분 유효한 서명 요청을 발행한다. 관리형 에이전트는 새 서명 계약을 지원할 때 요청을 확인한다. 호스트에서 명시적으로 차단했거나 최근 지원 보고가 없거나 정책이 제거를 금지하거나 업데이트 중인 대상은 미리보기에서 제외한다.
2. 에이전트는 현재 mTLS 등록에 묶인 요청 서명을 확인하고 로컬 챌린지에 대한 일회용 승인을 받는다. 승인과 시작 감사가 확인돼야 한다.
3. RPM을 제거하기 직전 센트럴에 시작 승인을 요청한다. 센트럴이 대상의 현재 등록과 사이트, 만료와 정책, 요청 계정의 현재 제거 권한을 확인한다. 등록 사이트나 계정 권한이 바뀐 경우 시작을 허용하기 전에 요청을 취소한다. 운영자는 시작 승인이 기록되기 전까지 개별 요청을 취소할 수 있다.
4. 패키지 부재 확인 보고를 받아야 센트럴이 제거 성공을 기록하고 해당 등록의 인증서를 무효화한다. 시작 전 만료는 새 요청을 허용한다. 시작 뒤 결과가 없으면 결과 미확인으로 표시하고 해당 등록의 제거·업데이트를 대기시킨다.

기존 현장용 제거 승인과 등록 해지는 각각의 권한으로 관리한다. 시스템 차원의 공용 릴리스 관리와 센트럴 자체 업데이트 권한은 별도로 부여한다.

## 검증

정상 mTLS 연결에서 제한된 사이트 역할로 일괄 요청을 발행하고 모의 RPM 작업자가 완료를 보고하는 흐름을 확인한다. 다른 사이트의 명시 ID와 그룹 사용, 요청자가 제거 권한을 잃은 경우, 등록 이동, 미리보기 이후 변경, 취소 후 승인 재사용과 최종 보고의 재시도를 시험한다.
