# 보고된 서비스와 웹 출처 정책

## 목적

보안 정책의 탐지 탭에서 에이전트가 보고한 TCP 대기 서비스를 확인하고 정책 대상을 선택한다. 기존 적용 현황과 배포 흐름에서 실제 적용 범위를 확인할 수 있다.

## 정책 편집

| 대상 방식 | 저장 내용 | 배포 범위 |
| --- | --- | --- |
| 기존 기준 | 기존 실행 파일과 서비스 이름 | 이전과 같은 판정 |
| 지정된 서비스 | 직접 입력하거나 인벤토리에서 고른 정확한 systemd `.service` 이름 | 입력한 서비스 이름 |
| 발견된 모든 서비스 | 중앙 설정에 `all_listening`을 저장 | 각 서버가 최근에 보고한 정확한 시스템 서비스 이름 |

이 선택은 웹 출처 탐지와 해당 서비스 범위에 적용된다. 호스트 기본 탐지는 기존 엔진의 서비스 이름 비교와 프로세스 계보 판정을 사용한다. 전역 root·권한 탐지와 서비스별로 연결한 독립 정책은 각각의 규칙에 따라 적용된다. 기존 정책은 자동 변환하지 않는다. 확장 규칙의 탐지 전용 동작과 자동 종료 조건은 기존 계약을 따른다.

## 서비스 인벤토리

센트럴은 관리형 에이전트의 `inventory.listening_services` 하트비트를 읽는다. 현재 등록, 최근 중앙 수신과 표본 시각, 형식 및 보고 상한을 확인해 상태와 항목을 제공한다. 조회 화면은 포트, 주소 계열, 바인딩 범위, 확인 가능한 서비스 이름을 보여 준다.

미귀속 포트는 목록에서 확인할 수 있다. 부분 표본에 확인된 서비스를 지정 목록에 수동으로 넣을 수 있다. 오래된 표본은 시각과 함께 조회하며 대상 추가에는 사용하지 않는다. TCP 대기 보고는 외부에서 접속 가능한지 판정하지 않는다.

## 미리보기와 서명

발견된 모든 서비스는 각 서버의 최신 완료 표본에서 확인된 유닛을 얻는다. 표본이 누락·지연·부분 수집 상태이거나 확인된 유닛이 한 개도 없으면 해당 배포 시도를 명확한 이유와 함께 거절한다.

미리보기에는 같은 대상 목록을 가진 서버를 묶어 실제 서비스 이름을 표시한다. 확인용 토큰에는 서버별 목록의 해시를 넣고 배포 트랜잭션에서 다시 계산한다. 표본 시각이나 포트가 갱신돼도 이름 집합이 같으면 확인을 이어갈 수 있다. 대상 이름이나 등록이 바뀌면 다시 미리 본다.

에이전트에는 기존 서명 정책의 `detection.web_services`로 확정한 목록을 보낸다. 새로 열린 서버 서비스는 다음 명시적 배포에서 포함된다. 기존 정책 상세에서 서명된 실제 목록을 확인할 수 있다.

표본 비교를 사용하는 단계 배포에는 지정된 서비스와 기존 기준을 사용한다. 발견된 모든 서비스는 일반 배포에서 대상 한 대 또는 그룹을 선택할 수 있다.

## 검증

- 운영 에이전트가 만든 인벤토리 형식, 구형·미수집 상태, 일부 누락, 상한, 이전 등록 보고를 검증한다.
- 다른 목록을 가진 두 서버의 미리보기와 서명 결과, 미리보기 이후 이름 추가·삭제 시 재확인, 동일 목록 반복 보고를 검증한다.
- 실제 브라우저에서 보고된 서비스의 지정 추가, 기존 화면의 배포 미리보기, 두 서버의 적용 대상을 확인한다.
