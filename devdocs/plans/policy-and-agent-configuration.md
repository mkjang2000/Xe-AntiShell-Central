# 센트럴의 보안 정책과 에이전트 운영 설정

## 목적과 권한

센트럴의 관리자·운영자는 보안 정책과 지원되는 운영 설정을 편집하고 배포한다. 조회자는 조회한다. 운영자는 대상 그룹에 한 번 승인하고, 대상 에이전트가 각자의 등록 세대와 서명을 검증한다. 호스트 보안 경계 항목은 센트럴에서 조회 전용이다.

| 영역 | 관리 범위 | 적용 경로 |
| --- | --- | --- |
| **Security Policy · 보안 정책** | 탐지 대상·규칙·예외, 보호 범위, 대응, 일반 제거, 에이전트 파일 측정 | 기존 서명 정책. 실제 파일 측정은 별도 할당 |
| **Agent Configuration · 에이전트 운영 설정** | 자원 수집, 관측 보존, 선택형 센서, 개인정보, 리소스 한도, 로컬 패널 접근 | 현재 중앙 배포는 자원 모니터링 3개 필드. 나머지는 아래 원격 계약의 제안 |
| **Host Security Boundary · 호스트 보안 경계** | 등록 신뢰, 정책·RPM 검증 키, 로컬 종료·복구 허용, 서비스 계정·root 작업자·네트워크 경계 | 등록 기록과 하트비트에 있는 상태를 조회. 보고가 없으면 미확인 |

아래의 **현재**는 에이전트 r36과 센트럴 r21 계열의 코드에 있는 동작이다. **제안** 값은 차기 계약을 설계하기 위한 초기값과 범위다. 기본값은 새 템플릿이나 새 호스트의 기준이다. 기존 설정과 설치별 차이는 에이전트의 실효값으로 확인한다.

## Security Policy · 현재 편집하는 값

### 탐지 프로필과 대상

| 키 | 값과 기본값 | 무엇을 제한하는가 |
| --- | --- | --- |
| `detection.enabled` | Boolean. 기본 `true` | 탐지 엔진의 경보 평가를 켠다. `false`는 규칙 평가를 끄며 수집기 중지와는 별도다. 모의 대응과 자동 종료에는 `true`가 필요하다. |
| `detection.extended_process_rules` | Boolean. 기본 `false` | 웹 출처의 도구·인터프리터·임시 경로 실행 6종을 추가한다. 활성화하면 기본 웹 셸도 탐지 전용이다. Tetragon과 Linux audit의 실행 파일 포함 목록은 둘 다 비어 있어야 한다. |
| `detection.privilege_rules` | Boolean. 기본 `false` | 웹 출처와 무관한 root 실행·자격 증명 변경 프로필을 켠다. 센트럴에서 배포하려면 현재 등록의 Tetragon 정책 지원 보고가 필요하다. 정책 지원과 변경 센서의 실수신을 따로 표시한다. |
| `detection.root_exec_alerts` | `suspicious` 또는 `all`. 생략하면 `suspicious`. 권한 프로필이 꺼져 있으면 생략 | `suspicious`는 문맥 점수가 45 이상인 root 실행을 경보로 올린다. `all`은 낮은 점수의 일상적 root 실행도 포함한다. 이 값은 root 실행 경보에만 영향을 준다. |
| `detection.web_executables` | 실행 파일 이름 목록, 최대 256개. 중앙 기본 `httpd`, `apache2`, `nginx`, `php-fpm`, `gunicorn`, `uwsgi` | 부모·조상 프로세스의 실행 파일 이름으로 웹 출처를 지정한다. 전체 경로 대신 파일 이름을 입력한다. |
| `detection.web_services` | 서비스 이름 목록, 최대 1,024개. 기본 빈 목록 | 시스템에 귀속된 웹 서비스를 지정한다. 파일·TCP 범위의 서비스 이름은 이 목록과 대소문자까지 같아야 한다. 예시는 `catalog.service`다. |
| `detection.shells` | 실행 파일 이름 목록, 최대 64개. 중앙 기본 `sh`, `bash`, `dash`, `zsh`, `ksh`, `ash`, `busybox`, `fish`, `csh`, `tcsh` | 기본·확장 웹 셸 탐지에서 셸로 분류하는 이름을 정한다. 웹 출처 탐지를 사용하면 대상 호스트의 수집 필터가 이 이름을 수신할 수 있어야 한다. |
| `detection.allowed_pairs` | 문자열 목록, 최대 512개. 기본 빈 목록. 형식은 `출처:셸`, 예시는 `maintenance.service:bash` | 지정한 출처에서 지정한 셸이 실행될 때 셸 경보를 예외 처리한다. 별도의 임시 경로·인터프리터·파일·TCP 규칙에는 해당 규칙의 예외를 적용한다. |

서명 정책의 이름은 1~255바이트 ASCII다. 실행 파일 이름은 영문·숫자·점·밑줄·하이픈을 허용한다. 서비스·출처 식별자에는 `@`와 역슬래시도 허용한다. 공백·경로·단독 `.` 및 `..`은 거절한다. 위의 이름 목록과 허용 조합은 대소문자를 무시해 중복을 검사한다. 탐지가 켜져 있고 권한 프로필이 꺼져 있으면 웹 출처 한 개 이상과 셸 한 개 이상이 필요하다.

### 내장 규칙 ID

| 프로필 | 규칙 ID | 판단 범위 |
| --- | --- | --- |
| 기본 웹 셸 | `web-descendant-root-shell` · `web-descendant-shell` | 웹 서비스 계보의 root 셸과 일반 셸 실행. 확장 프로필이 꺼져 있을 때만 이 두 규칙이 대응 후보가 된다. |
| 확장 도구 | `web-descendant-download-tool` · `web-descendant-recon-tool` · `web-descendant-connection-tool` | 웹 출처에서 다운로드·시스템 확인·연결 도구가 실행된 사실 |
| 확장 인터프리터 | `web-descendant-inline-interpreter` · `web-descendant-temporary-executable` · `web-descendant-temporary-script` | 인라인 실행 옵션, 임시 경로의 실행 파일, 정확한 인수에서 확인된 임시 경로 스크립트. 해당 인수 또는 센서 근거가 있어야 한다. |
| root 권한 | `privilege-root-execution` · `privilege-root-restored` · `privilege-host-root-gain` · `privilege-root-identity-change` | 전역 root 실행, 기존 root 자격 복귀, 초기 사용자 네임스페이스 root 획득, 기타 root 신원 변경 |
| Linux Capability | `privilege-capability-gain` · `privilege-capability-activated` | 허용 권한 집합 증가 또는 기존 허용 권한이 유효 권한으로 활성화된 사실 |
| 서비스 파일·TCP | `service-protected-file-write` · `service-unexpected-tcp-destination` | 선택한 서비스의 보호 경로 쓰기와 허용 목적지 밖 TCP 연결 시작 |

서비스에서 `enabled`를 지정해도 상위 프로필 활성화, 서비스 귀속 및 센서 근거가 필요하다. 확장 프로세스·권한·파일·TCP 규칙은 탐지 전용이다. 개별 규칙의 점수는 규칙 버전이 정하고, 운영자는 `response.risk_threshold`로 대응 임계값을 정한다.

### 서비스별 제어와 만료 예외

| 키 | 값과 기본값 | 무엇을 제한하는가 |
| --- | --- | --- |
| `detection.service_rule_controls` | 객체 배열, 최대 256개. 기본 생략. 빈 배열은 기본 프로필 동작 | 서비스·규칙으로 묶인 예외만 적용한다. 같은 서비스와 규칙 조합을 한 번만 지정한다. |
| `service_rule_controls[].service` | 정확한 서비스 이름 문자열. `unknown` 제외 | 서비스 귀속을 확인한 이벤트에 적용할 범위다. 호스트 전체나 모든 서비스를 뜻하는 와일드카드는 없다. |
| `service_rule_controls[].rule_id` | 위 16개 ID 중 하나 | 켜거나 끌 규칙을 선택한다. |
| `service_rule_controls[].mode` | `enabled`, `disabled`, `suppress_until` | `enabled`는 해당 프로필 안에서 규칙을 허용하고, `disabled`는 해당 서비스에서 비활성화한다. `suppress_until`은 만료 시각까지 억제하고 이후 다시 평가한다. |
| `service_rule_controls[].reason` | `suppress_until`에서 필수. UTF-8 1~512바이트. 앞뒤 공백과 제어문자 금지 | 일시 예외의 승인 사유를 기록한다. 나머지 모드에서는 생략한다. |
| `service_rule_controls[].expires_at` | `suppress_until`에서 필수. RFC 3339 UTC, 예시 `2026-12-01T05:00:00Z` | 만료 시각부터 억제를 해제한다. 이미 만료한 값은 해제된 예외로 계산한다. 나머지 모드에서는 생략한다. |

### 서비스별 파일·TCP 보호 범위

| 키 | 값과 기본값 | 무엇을 제한하는가 |
| --- | --- | --- |
| `detection.service_observations` | 서비스 객체 배열, 최대 64개. 기본 생략 | 생략하면 호스트 YAML을 사용한다. `[]`는 파일·TCP 범위를 모두 끈다. 객체 목록은 호스트 범위를 전부 교체한다. `null`은 거절한다. |
| `service_observations[].service` | 정확한 서비스 이름. 목록에서 고유하며 `unknown` 제외 | 이 서비스에 속한 파일 쓰기와 TCP 시작만 평가한다. `web_services`와 불일치하면 현재 미리보기에 경고하고 에이전트에서 해당 범위를 적용하지 않는다. |
| `service_observations[].protected_dirs` | 정규화된 Linux 절대 경로 목록, 최대 32개. 각 경로 최대 4,096바이트. 기본 빈 목록 | 경로 아래에서 확인된 쓰기를 경보 후보로 본다. 예시는 `/srv/catalog`다. 빈 목록은 해당 서비스의 보호 경로 쓰기 규칙을 끈다. |
| `service_observations[].allowed_write_dirs` | 위와 같은 경로 형식, 최대 32개. 기본 빈 목록 | 보호 디렉터리 또는 그 하위에 해당하는 쓰기 예외다. 예시는 `/srv/catalog/uploads`다. 한 경로가 보호와 예외 양쪽에 해당하면 쓰기 예외가 우선한다. |
| `service_observations[].allowed_tcp_destinations` | `{cidr, ports}` 객체 배열, 최대 32개. 기본 빈 목록 | 같은 항목 안의 CIDR·포트 조합 중 하나라도 일치하면 허용 범위다. 빈 배열은 해당 서비스의 TCP 규칙을 끈다. |
| `allowed_tcp_destinations[].cidr` | IPv4 또는 IPv6 네트워크 CIDR. 예시 `192.0.2.0/24`, `2001:db8:10::/64` | 목적지 주소 범위를 지정한다. 호스트 비트가 켜진 CIDR과 IPv4-mapped IPv6 CIDR은 거절한다. |
| `allowed_tcp_destinations[].ports` | 중복 없는 정수 목록, 최대 64개, 범위 1~65,535. 생략 또는 `[]`이면 해당 CIDR의 모든 포트 | 지정 CIDR에서 허용할 TCP 목적지 포트를 제한한다. 예시 `[443, 8443]`. |

각 서비스에는 보호 디렉터리 또는 허용 TCP 목적지가 최소 하나 있어야 한다. 디렉터리 목록은 중복 없이 입력하며 `..` 같은 비정규 경로는 거절한다. 범위는 수신한 경로의 구성 요소를 기준으로 비교한다. 현재 파일 규칙은 양수 바이트가 쓰인 경우, TCP 규칙은 연결을 시작한 경우를 평가한다. 삭제·이름 변경·권한 변경과 TCP 연결 성립 여부는 별도 후속 항목이다.

### 대응과 제거

| 키 | 값과 기본값 | 무엇을 제한하는가 |
| --- | --- | --- |
| `response.mode` | `observe` 기본, `would_block`, `enforce` | `observe`는 탐지 기록, `would_block`은 대응 후보 기록, `enforce`는 대상이 확인된 실행 후 종료 시도다. |
| `response.action` | `none` 기본, `terminate` | 실제 제공하는 대응 동작은 `terminate`다. 관찰 모드의 기존 템플릿은 다음 배포용으로 `terminate` 값을 저장할 수 있다. |
| `response.risk_threshold` | 정수 0~100. 기본 `90` | 이 점수 이상인 탐지만 대응 후보로 검토한다. 모의 대응과 자동 종료에서 `0`은 거절한다. |
| `response.min_confidence` | 유한한 수 0~1. 기본 `0.95`. 현재 화면은 0.01 단위 | 대응 판단에 필요한 최소 근거 신뢰도다. 모의 대응과 자동 종료에서 `0`은 거절한다. |
| `response.required_capabilities` | 기능 키 문자열 목록, 최대 32개. 기본 빈 목록. 관찰 이외에는 최소 1개 | 모든 키에 구현 및 실제 동작 근거가 있어야 한다. 콘솔 기본 선택 항목은 `observation.process_exec`, `observation.process_lineage`, `response.terminate`, `collector.tetragon`, `collector.audit`, `kernel.ebpf`다. 직접 입력한 기존 키도 저장할 수 있고 대상이 보고하지 않으면 조건이 충족되지 않는다. |
| `uninstall_mode` | `approval_required` 기본, `allow`, `deny` | 현재 관리형 일반 제거는 `approval_required`와 `allow` 모두 일회용 중앙 서명 승인과 감사 ACK가 필요하다. `deny`는 일반 제거를 거절한다. 등록별 오프라인 비상 복구는 호스트 보안 경계에서 따로 취급한다. |
| `validity_hours` | 센트럴 템플릿의 정수 1~8,760시간. 기본 `24` | 배포 시 발행·만료 시각을 계산한다. 만료하면 마지막 승인 탐지를 유지하고 자동 대응을 중지한다. |

모의 대응과 자동 종료에는 탐지 활성화, `terminate`, 양수 임계값 두 개, 기능 조건 한 개 이상이 함께 필요하다. 두 수집기를 동시에 필수로 선택하면 조건을 충족할 수 없다. `enforce`는 실행·계보·pidfd 종료 조건을 항상 확인한다. 호스트 로컬 종료 허용이 꺼져 있거나 pidfd가 지원되지 않으면 에이전트가 `enforce` 정책을 거절한다. 확장 프로필의 종료 후보가 0개여도 이 수락 조건은 적용된다.

### 파일 무결성과 저장된 이전 초안

| 키 | 값과 기본값 | 무엇을 제한하는가 |
| --- | --- | --- |
| `integrity.package_files` | Boolean, 기본 `false` | 현재 승인된 패키지의 실행 파일 4개, systemd 유닛 3개와 사이트 YAML, 보관된 서명 정책의 측정을 요청한다. 패키지 파일 기준은 검증한 RPM에서 얻는다. |
| `integrity.config_sha256` | 생략·빈 값 또는 소문자 16진수 64자리. 해시를 입력하려면 `package_files: true` | 사이트 YAML과 승인한 기대값을 비교한다. 기대값이 없으면 기준 미등록으로 표시한다. |
| 이전 초안 `integrity.enabled` · `integrity.require_tpm` | 각 Boolean, 기본 `false` | 저장된 초안의 활성 여부와 TPM 조건이다. 화면에서 조회만 가능하다. |
| 이전 초안 `integrity.mode` | `observe` 기본 또는 `enforce` | 저장된 초안에 적힌 검증 방식이다. 실제 파일 무결성 검사는 결과를 보고한다. |
| 이전 초안 `integrity.paths` | 정규화된 고유 절대 경로 목록, 최대 256개, 각 4,096바이트. 기본 `[]` | 과거 템플릿에 저장된 후보 경로다. 현재 측정 경로는 제품이 정한 목록이다. |

무결성은 정책 본문의 서명과 별도로 등록 ID·정책 리비전·서명 정책 다이제스트에 묶인 측정 할당으로 전달한다. 에이전트는 같은 할당을 한 시간마다 다시 측정하고, 센트럴은 파일별 측정 시각과 기준값을 바탕으로 일치·예상 밖 변경·누락·읽기 실패·기한 경과를 표시한다. 현재 최신성 기준은 2시간이다. 다른 필드를 저장할 때 이전 초안 값은 보존한다.

### 배포 승인과 적용 상태

- 템플릿 저장, 그룹 편집, 실제 배포는 별도 작업이다. 대상은 개별 에이전트와 최대 64개 그룹의 합집합이며 최대 1,000대로 제한한다. 미리보기의 승인 기한은 5분이다.
- 서명 정책은 대상 에이전트·등록 ID·상승하는 리비전·발행 및 만료 시각을 검증하며 서명 봉투의 최대 크기는 64KiB다. 센트럴 템플릿의 `validity_hours`와 직접 정책 API의 최대 유효 기간 366일은 각각 별도 입력 제한이다. 직접 서명 정책의 `schema_version`은 문자열 `"1"`이다. `policy_id`·`agent_id`는 1~128바이트, `enrollment_id`는 1~160바이트 문자열이다. 세 ID에는 ASCII 영문·숫자·하이픈·밑줄·점·콜론을 허용한다. `revision`은 1~9,223,372,036,854,775,807의 정수다. `issued_at`과 `expires_at`은 RFC 3339 시각이며, 발행 시각이 현재보다 1분 넘게 미래거나 이미 만료됐으면 에이전트가 거절한다.
- 파일·TCP 범위(명시한 빈 목록 포함), 비어 있지 않은 서비스별 규칙 목록, 활성화한 권한 프로필을 새로 발급하려면 현재 등록의 최근 2분 하트비트에 해당 계약 지원 근거가 있어야 한다. 센서 수신이 미확인인 경우와 정책 계약 자체가 지원되지 않는 경우는 별도로 표시한다.
- 파일·TCP 경보는 r34부터 로컬 범위를, r35부터 서명된 중앙 범위를 지원한다. 서비스별 규칙·만료 예외와 파일 무결성은 r36부터 지원한다. 예전 에이전트와 최신 에이전트가 섞인 그룹에서 새 기능을 배포할 때는 지원 대상을 확인한다.
- 대상·등록·그룹·템플릿·기준 정책이 달라지면 다시 미리보기한다. 같은 표본의 현행·후보 비교, 한 대 선행 적용, 그룹 확대, 이전 정책을 내용으로 하는 상위 리비전 복구를 사용한다.
- 화면에서 요청 리비전, 실제 적용 리비전, 수락·거절·만료, 경보와 센서 근거를 함께 조회한다. 이전 초안과 파일 측정 요청은 서명 정책의 적용 상태와 구분한다.

### 애플리케이션별 정책 · 제안

한 관리형 에이전트에 **호스트 기본 정책 한 개와 애플리케이션별 정책 여러 개**를 지정한다. 기존 서비스별 규칙 제어는 개별 경보를 끄거나 일시 억제한다. 이 기능은 애플리케이션마다 탐지 프로필, 예외, 파일·TCP 범위, 대응 모드·임계값을 선택할 수 있게 확장한다. 자원 수집과 일반 제거, 호스트의 로컬 종료 허용은 호스트 단위로 관리한다.

| 대상 예시 | 정책 | 동작 |
| --- | --- | --- |
| `nginx.service` | `nginx-shell-stop` v3 · 기본 웹 셸 프로필 · `enforce` | 확인된 nginx 자손 셸이 임계값과 호스트 종료 허용 조건을 모두 충족하면 실행 후 종료를 시도한다. |
| `pm2-deploy.service` | `pm2-monitor` v2 · `observe` | PM2에 귀속된 동작을 탐지·기록하고 자동 종료를 하지 않는다. 특정 정상 배포에서 경보까지 억제할 때는 서비스·규칙·기간을 지정한 별도 예외를 사용한다. |
| 지정되지 않았거나 귀속을 확인할 수 없는 실행 | 호스트 기본 탐지 · `observe` | 기본 탐지를 사용하고, 대응 후보가 보류된 경우 그 이유를 기록한다. |

표의 서비스명은 예시이며 콘솔에서 에이전트가 실제로 관측한 이름을 확인해 지정한다. 화면의 ‘허용’은 `observe`, 즉 **자동 종료 없이 관찰**한다는 의미다. nginx 앞단에서 PM2로 프록시하는 경우에도 대응 대상은 요청이 경유한 서버가 아니라 이벤트가 발생한 프로세스의 서비스 귀속으로 정한다. `enforce`의 현재 동작 범위는 웹 셸의 실행 후 종료 시도다.

#### 입력과 정책 선택

| 입력 | 제안 값과 제한 |
| --- | --- |
| 앱 표시 이름 | 운영자가 지정하는 표시 이름. 정책 매칭에는 서비스 식별자를 사용한다. |
| 서비스 선택자 | 첫 버전은 정확히 일치하는 시스템 범위 systemd 서비스 유닛 한 개. 예시는 `nginx.service`다. 와일드카드·실행 파일 이름·포트·도메인만으로 자동 종료 권한을 지정하는 입력은 제공하지 않는다. |
| 정책 참조 | 저장된 정책 ID와 고정 버전. 호스트의 기본 정책과 앱용 정책을 미리보기에서 각각 선택한다. |
| 대응 모드 | `observe`, `would_block`, `enforce`. 앱별로 독립 설정한다. 해당 앱에서 확장 프로필을 켜면 현재 규칙 의미에 따라 대응 대상은 0개다. |
| 대상 | 호스트 또는 서버 그룹. 각 호스트의 결과에는 정확한 서비스 하나당 정책 하나를 둔다. 첫 버전은 호스트당 최대 64개 항목을 제안하며 기존 서명 본문 크기 제한을 함께 적용한다. |

1. 에이전트는 수집 이벤트의 직접 서비스 귀속을 확인해 해당 서비스에 지정된 정책 하나를 선택한다. 앱 정책을 선택하면 그 버전의 대응 모드와 임계값을 함께 사용한다. 공통 규칙과 앱 규칙이 둘 다 같은 경보를 중복 생성하지 않도록 평가 범위를 구분한다.
2. 서로 다른 그룹이 같은 호스트·서비스에 다른 정책을 지정하면 중앙에서 충돌을 표시하고 배포를 거절한다. 같은 정책·버전이 반복 지정되면 한 번으로 합친다. 검증된 일치가 없거나 증거가 충돌하면 기본 탐지만 적용한다. 종료 직전에는 기존 대상 신원 검사와 함께 서비스 귀속을 다시 검증한다.
3. PM2 앱 여러 개가 하나의 서비스에 속하면 첫 버전의 정책 단위도 그 서비스 하나다. 앱마다 다른 정책이 필요하면 각각 독립적으로 확인할 수 있는 서비스 단위가 필요하다.
4. 센트럴이 기본 정책과 앱별 정책의 버전·정책 내용 해시·서비스 매핑을 하나의 호스트용 정책으로 확정하고 서명한다. 에이전트는 지원과 서명·등록·리비전을 확인한 뒤 전체를 한 번에 적용한다. 템플릿 편집은 이미 배포한 정책을 바꾸지 않으며, 구버전 에이전트에는 기존 정책을 유지한다. 정책이 만료되면 마지막 승인 탐지는 유지하고 모든 앱의 자동 종료를 중지한다. 변경과 복구는 모두 새 상위 리비전으로 발행한다.

#### 센트럴에서 조회할 화면

- **정책 전체 목록**에는 정책 이름·버전, 사용 중인 서비스와 대상 호스트·그룹, 배포 상태를 표시한다. 정책을 열면 해당 버전의 규칙·예외·범위·대응 설정을 펼쳐 볼 수 있다.
- **에이전트별 적용 정책**에는 호스트 기본 정책과 앱별로 서비스·정책 ID/버전·대응 모드·적용 상태를 표시한다. 센트럴의 목표 리비전과 에이전트가 보고한 적용 리비전을 나란히 보여 주고, 적용된 리비전의 전체 내용을 펼쳐 볼 수 있게 한다. 호스트가 따로 정한 값은 출처와 확인 시각을 표시하고, 근거가 없으면 미보고로 표시한다. 호스트가 정책 묶음을 적용했다는 보고와 개별 앱에서 규칙이나 센서가 실제 동작했다는 증거를 구분한다.
- **배포 미리보기와 탐지 이력**에는 달라질 서비스 매핑, 귀속 미확인이나 지원 부족, 예상 대응 후보를 표시한다. 탐지 상세에서는 어떤 서비스·정책 버전·호스트 리비전으로 평가했는지 확인할 수 있게 한다.

격리 검증에서는 nginx와 PM2가 같은 호스트에 있을 때 같은 셸 실행도 각 서비스의 대응 정책으로 평가하는지 확인한다. nginx 계보와 PM2 직접 귀속이 상충하는 표본, 유사 이름, 공유 서비스, 대상 신원 재검증 실패에서는 오종료가 없어야 한다. 그룹 충돌, 미지정·귀속 불명, 구버전 혼재, 템플릿 편집 후 기존 버전 보존, 적용 거절·보고 누락·상위 리비전 복구도 함께 검증한다.

## Agent Configuration · 현재 값과 원격 허용 제안

### 자원 모니터링과 하트비트

현재 이 세 필드는 센트럴에서 편집할 수 있고 서명 정책의 `monitoring`에 들어간다. 자원 부분의 전송 예산은 384KiB이며, 이를 넘을 때는 프로세스 목록이 설정한 한도보다 작아질 수 있다. 다음 계약에서도 의미가 같은 항목과 달라지는 항목을 구분한다.

| 키 | 현재 허용값과 기본값 | 무엇을 제한하는가 | 차기 계약 제안 |
| --- | --- | --- | --- |
| `monitoring.enabled` | Boolean. 기본 `true` | CPU·메모리·파일시스템·디스크 I/O·네트워크 인터페이스·프로세스 자원 표본을 수집한다. `false`에서도 연결과 정책 상태를 하트비트로 보고한다. | 같은 값과 기본값. 자원 수집만 제어 |
| `monitoring.sample_interval_seconds` | 정수 5~3,600초. 기본 `10` | 현재는 자원 표본과 하트비트 전송 간격을 함께 바꾼다. 120초 이상에서는 네트워크 지연까지 더해지면 기존 2분 신선도 검사에서 보고가 오래된 것으로 표시될 수 있다. | 범위와 기본값을 유지하고 자원 샘플링에만 사용. 샘플 시각을 같이 보내며, 하트비트 주기만으로 표본을 다시 수집하지 않음 |
| `monitoring.process_limit` | 정수 1~2,000개. 기본 `200` | 한 표본에 포함할 프로세스 항목 수를 제한한다. 운영체제의 프로세스 개수나 행위 탐지를 제한하지 않는다. | 같은 범위 안에서 호스트가 더 낮은 상한 설정 가능 |
| 하트비트 간격 | 현재 별도 입력 없음 | 연결 상태·등록·정책 적용 상태와 기능 지원 판단에 사용한다. | 신계약 초기값 10초, 조회 전용으로 제안. 하트비트와 자원 표본에 각각 시각을 표시 |

### 이벤트 보존과 개인정보

로컬 키는 현재 RPM의 YAML 키다. 차기 원격 키는 제안이며, 로컬 보존 설정을 읽어 자동 전송하는 동작은 별도 구현한다.

| 항목 | 현재 로컬 값과 기본값 | 첫 원격 허용 제안 | 제한 대상과 검증 |
| --- | --- | --- | --- |
| 일반 관측 보존 | `limits.observation_history_minutes` 정수 0~1,440분. RPM 기본 `60`. `0`은 일 단위 보존과 기존 전체 관측 저장 방식 사용 | `retention.observation_history_minutes` 정수 **60~1,440분**. 필드 생략은 기존 출처 유지 | 양수는 일반 관측을 축소해 저장하고 만료시킨다. 경보 근거와 전송 대기 자료에는 기존 보호 조건을 적용한다. 기간 단축은 만료 예상량과 디스크 상황을 미리 보고 승인한다. 이미 지운 이력은 값을 되돌려도 복구되지 않는다. |
| 일 단위 보존 | `limits.retention_days` 정수 1~3,650일. 기본 `7` | 로컬 관리 | 일반 관측 분 단위 설정이 `0`일 때의 보존 기준이다. 이미 존재하는 다른 영구 자료의 보존 정책과 구분한다. |
| 원본 이벤트 저장 | `privacy.store_raw_events` Boolean. 기본 `false` | 첫 원격 계약에서 제외. 이후 `privacy.store_raw_events: false`만 허용하는 방향 | 원시 수집기 JSON을 보관할지 결정한다. 축소 저장 모드와 일부 이벤트 유형은 별도로 원본을 버린다. 원격에서 원본 저장을 켜는 값은 제공하지 않는다. |
| 명령 인수 마스킹 | `privacy.redact_argv` Boolean. 기본 `true` | 첫 원격 계약에서 제외. 이후 `privacy.redact_argv: true`만 허용하는 방향 | 민감 인수로 확인된 값을 가린다. 명령·파일·환경 전체를 익명화하는 기능과 구분한다. |
| 민감 인수명 | `privacy.sensitive_argument_names` 문자열 배열. 마스킹이 켜져 있으면 최소 하나 필요. 기본 `password`, `passwd`, `token`, `access-token`, `api-key`, `apikey`, `secret`, `client-secret`, `authorization` | `privacy.additional_sensitive_argument_names`에 키 이름만 추가. 최대 64개, 각각 1~64자 ASCII 영문·숫자·밑줄·하이픈 제안 | 로컬에 있는 이름을 보존한 채 중앙 목록과 합친다. 케이스를 정규화해 중복 제거한다. 값·비밀번호·정규식은 이 필드에서 다루지 않는다. |

현재 일반 관측 만료는 양수 분 단위 설정에서 1분마다, 일 단위 설정에서 6시간마다 나눠 처리한다. 보존 시간은 만료 기준 시각이며 정리 완료까지 걸리는 시간을 별도로 표시한다. 에이전트 용량 보고의 보존 기간과 축소 저장 여부는 문자열로 전달된다. 콘솔이 숫자·Boolean으로 엄격하게 변환하고, 정상값 `0`과 필드 미보고를 구분하도록 한다. 센트럴이 보존하는 관측 이력은 이 에이전트 정책과 별도로 운영한다.

### 수집기와 선택형 센서

| 항목 | 현재 값과 기본값 | 원격 허용 제안 | 제한 대상과 검증 |
| --- | --- | --- | --- |
| `collector.mode` | `auto` 기본, `tetragon`, `audit`, `replay`, `disabled` | 최초 계약에서는 선택된 수집기와 상태만 조회. 전환 기능은 이후 사전 정의된 `auto`·`tetragon`·`audit` 프로필과 호스트 허용 목록이 있을 때 검토 | 실제 실행 이벤트의 출처를 고른다. `auto`는 사용 가능한 Tetragon을 우선하고 Linux audit를 대체 수집기로 사용한다. 하트비트의 선택된 수집기와 호스트에 설정한 모드를 구분한다. |
| `collector.tetragon.command` · `args` | 절대 경로와 문자열 배열. RPM 기본 명령 `/usr/bin/tetra`, 인수 `["getevents", "-o", "json"]` | 로컬 관리 | 실행할 바이너리와 수집 스트림을 정한다. 센트럴은 명령·인수나 커널 정책 원문을 원격 입력으로 받지 않는다. |
| `collector.audit.input_path` · `collector.replay.path` | 로컬 경로. 기본 빈 값. 리플레이 모드에서는 경로 필수 | 로컬 관리 | 운영 입력·시험 파일 경로다. 현재 audit 수집 경로는 디스패처이며 YAML의 `input_path`를 지정해 임의 로그 파일을 읽는 계약은 없다. |
| `include_executables` | Tetragon·audit별 실행 파일 이름 목록. 기본 `[]` | 로컬 관리 | 비어 있으면 포함 목록으로 제한하지 않는다. 목록을 입력하면 탐지에 필요한 실행 파일까지 누락될 수 있으므로 확장 프로필은 양쪽 목록이 비어 있어야 한다. |
| `only_detection_origins` | Tetragon·audit별 Boolean. 기본 `false` | 초기에는 조회·로컬 관리 | 적용된 탐지의 웹 출처에 맞춰 관측을 좁힌다. 활성화하려면 탐지 활성화가 필요하다. 전역 권한 센서와 필수 근거가 영향을 받는지 검증한다. |
| 선택형 파일 쓰기·TCP·인라인·권한 센서 | 현재 고정된 센서 구현과 호스트 수집 설정, 정책 지원 근거를 사용. 중앙의 공통 센서 스위치는 없음 | 이후 `collector.optional_sensors`에 사전 정의된 Boolean 키 `file_write`, `tcp_connect`, `inline_exec`, `credential_change`를 개별 허용. 생략은 기존 출처 유지 | 지원과 로컬 허용을 확인한 센서만 요청한다. 사용 중인 보안 규칙이 해당 센서를 요구하면 끄기 요청을 거절한다. 적용 후 센서 실행 상태와 최근 이벤트 수신 여부를 분리해 보고한다. |

파일·TCP 범위는 **Security Policy**에서 정하고, 해당 이벤트를 관측할 수 있는지는 위 수집 설정과 센서 상태에서 확인한다. 적용에 센서나 서비스 재기동이 필요하면 대상별 미리보기에서 표시한다.

### 처리·저장·조회 한도

| 현재 키 | 현재 기본값과 검증값 | 제한하는 대상 | 원격 허용 제안 |
| --- | --- | --- | --- |
| `limits.max_event_bytes` | 정수 262,144바이트. 최소 1,024바이트. 큐 크기와의 곱 조건도 적용 | 처리할 이벤트 한 건의 크기 한도 | 부하 검증 이후 65,536~262,144바이트 제안. 대상 정책의 수집 근거가 누락될 수 있는 축소는 거절 |
| `limits.max_raw_json_bytes` | 정수 131,072바이트. 범위 0~`max_event_bytes` | 원시 JSON 보관 시 한 건의 크기 한도 | 로컬 관리. 원본 보관 여부와 함께 평가 |
| `limits.max_argv` · `max_argument_bytes` | 각각 정수 128개와 4,096바이트. 범위 1~65,536개와 1~`max_event_bytes` | 인수 개수와 개별 인수 크기 | 로컬 관리. 일부 인터프리터 탐지에서 필요한 인수의 완전성을 확인 |
| `limits.queue_size` | 정수 256개. 범위 1~1,000,000개. `queue_size × max_event_bytes`는 최대 512MiB | 수집과 로컬 처리 사이 버퍼의 레코드 수 | 부하 검증 이후 64~1,024개 제안. 로컬 예산 및 곱 조건 적용. 현재 시작 시 생성되므로 재기동 또는 별도 적용 로직 필요 |
| `limits.query_default` · `query_maximum` | 각각 정수 100개와 1,000개. `1 ≤ 기본 ≤ 최대 ≤ 100,000` | 로컬 Unix API의 조회 요청당 기본·최대 항목 수 | 이후 개방 검토. 최초 계약에서는 조회·로컬 관리 |
| 전송 스풀 상한 | 제품에서 256MiB로 고정 | 센트럴의 확인을 기다리는 자료의 총 저장 바이트 | 조회만 제공. 이후 조정이 필요하면 미전송 자료를 보존하고 현재 사용량보다 작은 상한은 거절 |
| 호스트 디스크 예산 | 호스트에서 관리. 보존 기간으로 디스크 크기를 직접 보장하는 현재 계약은 없음 | 관측 보존과 전송 스풀이 사용할 여유 공간 | 중앙 요청 적용 전 여유 공간과 사용 추세를 검사한다. 부족하면 기존 실효값을 유지하고 이유를 보고 |

표의 이벤트 바이트와 전송 스풀은 각각 이벤트 한 건과 전송 대기 전체에 대한 다른 한도다. 운영 화면은 둘 다 단위를 표시한다. 큐의 현재 적체와 이전에 기록된 드롭 수치도 따로 본다.

### 로컬 웹패널 접근

로컬 웹패널은 해당 서버를 직접 관리하는 사람이 에이전트 상태와 관측 정보를 조회하는 부가 기능이다. 센트럴 운영자는 중앙에 들어오는 보고를 중앙 콘솔에서 조회한다. 로컬 웹패널의 데이터 API는 조회용이며 로그인과 로그아웃 서버 세션 동작만 별도로 제공한다.

| 항목 | 값과 기본 동작 | 무엇을 제한하는가 |
| --- | --- | --- |
| `local_panel.access` | 차기 계약의 열거형 `allow` 또는 `block`. 새 필드는 생략이 기본이며 기존 호스트 동작을 이어받는다. | 허용은 호스트에 이미 구성된 패널에서 기존 로컬 인증으로 조회할 수 있게 한다. 차단은 로그인·화면·정적 자원·조회 API를 포함한 모든 패널 HTTP 요청에 `403`을 반환한다. |
| 상속 | `inherit: ["local_panel.access"]` | 중앙의 패널 접근 결정을 해제하고 호스트의 기준값을 사용한다. 단순 필드 생략은 마지막 결정과 적용 상태를 유지한다. |
| 호스트의 패널 구성 | 서비스 실행·바인딩 주소·포트·계정·인증·방화벽·프록시·TLS는 호스트 관리 | 서비스 시작 여부와 노출 범위를 호스트가 정한다. 중앙에서 `allow`를 선택해도 호스트의 차단과 기존 인증이 적용된다. |
| 적용 상태 | 제안은 요청값, 실효값, 적용 리비전과 시각, 정책 또는 호스트가 제한한 사유를 표시 | 서명 설정 수신과 실제 HTTP 차단 확인을 구분한다. 패널이 미기동이거나 최신 보고가 없으면 그 사실을 표시한다. |

에이전트가 검증·보관한 접근 결정을 웹패널 프로세스가 읽고, 인증 여부와 관계없이 전체 요청 진입점에서 적용한다. `block` 전환은 기존 로그인 쿠키를 무효화하고 진행 중인 패널 조회를 취소한다. 이미 열린 연결의 다음 요청도 막는다. 재허용 시 다시 로그인하고, 중앙 통신 단절이나 에이전트 재시작 후에도 마지막 적용된 차단을 유지한다. 에이전트의 센서, 중앙 전송·하트비트·ACK, 호스트의 로컬 CLI는 패널 접근의 적용 대상과 분리한다.

### 원격 운영 설정 요청과 실효값

차기 계약은 에이전트·등록 세대·기준 리비전·새 리비전·유효기간을 기존 보안 정책과 구분되는 서명 문맥으로 묶는다. 최초 적용 때는 기존 서명 정책의 `monitoring`을 기본으로 이어받는다. 필드별 첫 `set` 또는 `inherit`가 적용되면 새 계약이 해당 필드를 관리한다. 이후 일반 보안 정책을 다시 배포해도 그 필드는 새 계약의 중앙 값 또는 명시적으로 상속한 로컬 값을 사용한다. 에이전트는 필드별 실효 출처를 보고한다. 독립 에이전트는 로컬 설정을 사용하고 기존 관리형 에이전트에는 현재 서명 경로를 유지한다.

| 입력·상태 | 제안 동작 |
| --- | --- |
| `set` | 명시한 키와 값을 중앙 요청으로 지정한다. `false`와 숫자 `0`은 값으로 처리하며, 해당 항목의 허용 범위를 각각 검사한다. |
| 필드 생략 | 기존 요청 및 실효 출처를 유지한다. |
| `inherit` | 허용 키의 배열이다. 지정한 중앙 재정의를 해제하고 이 호스트의 로컬 값을 사용한다. |
| `null`·알 수 없는 키·중복·`set`과 `inherit` 충돌 | 요청을 거절하고 항목과 이유를 표시한다. 범위를 벗어난 값은 자동 보정하지 않는다. |
| 로컬 허용 범위 초과 또는 활성 보안 정책과 충돌 | 에이전트가 적용을 거절하고 직전 설정과 정책을 유지한다. |
| 서명 불일치·만료·대상 등록 불일치·과거 리비전 | 적용을 거절한다. 이미 성공한 현행 리비전의 동일 명령은 중복 실행 없이 결과를 보고한다. |
| 적용 실패·기동 확인 실패 | 직전 값으로 복구하고 실패 항목, 마지막 적용 리비전, 확인 시각을 보고한다. 연결이 끊기거나 적용 승인 기한이 지나도 이미 적용된 운영 설정은 마지막 값을 계속 사용한다. |

첫 원격 계약은 **별도 자원 샘플링과 일반 관측 보존**부터 연다. 로컬 웹패널은 동일한 서명 계약에서 `local_panel.access`만 추가하고, 접근 제어 지원과 실제 적용 보고를 검증한 대상에 제공한다. 예를 들어 로컬 보존이 60분이고 호스트가 240분을 상한으로 승인했다면, 중앙 요청 120분은 검증 후 적용할 수 있다. 480분은 거절되고 실효값 120분은 유지된다. 다음 리비전에서 상속을 지정하면 로컬 60분으로 돌아간다. 기간 단축 미리보기의 승인 조건은 상속에도 적용한다.

제안 값은 [에이전트 로컬 기본 설정](https://github.com/mkjang2000/Xe-AntiShell/blob/v0.1.0-r36/configs/sentineld.yaml)과 [현재의 YAML 검증](https://github.com/mkjang2000/Xe-AntiShell/blob/v0.1.0-r36/internal/config/config.go), [하트비트 동작](https://github.com/mkjang2000/Xe-AntiShell/blob/v0.1.0-r36/internal/agent/managed_worker.go)을 기준으로 정리했다.

### 값 입력 예시

다음은 **현재 보안 정책 템플릿의 탐지 필드 일부**다. 보호 경로 쓰기와 TCP 범위를 같은 서비스에 적용하고, 정해진 시간까지 그 서비스의 파일 경보를 억제한다.

```json
{
  "web_services": ["catalog.service"],
  "service_observations": [{
    "service": "catalog.service",
    "protected_dirs": ["/srv/catalog"],
    "allowed_write_dirs": ["/srv/catalog/uploads"],
    "allowed_tcp_destinations": [{"cidr": "192.0.2.0/24", "ports": [443]}]
  }],
  "service_rule_controls": [{
    "service": "catalog.service",
    "rule_id": "service-protected-file-write",
    "mode": "suppress_until",
    "reason": "승인된 정기 배포",
    "expires_at": "2026-12-01T05:00:00Z"
  }]
}
```

독립 에이전트의 로컬 YAML에서는 범위 목록 `service_observations`가 최상위에 있고, 위와 같은 서명 정책의 JSON에서는 `detection` 아래에 있다.

다음은 **차기 운영 설정 계약의 제안 본문 일부**다. 중앙에서 자원 표본 주기를 30초로 지정하고 로컬 웹패널 접근을 차단하며, 일반 관측 보존에 대한 중앙 재정의를 해제한다. 패널 접근 계약을 지원하는 대상에서 사용하는 예시다.

```json
{
  "set": {"monitoring": {"sample_interval_seconds": 30}, "local_panel": {"access": "block"}},
  "inherit": ["retention.observation_history_minutes"]
}
```

## Host Security Boundary · 조회 전용

이 영역에서 입력할 수 있는 값은 조회할 에이전트 선택뿐이다. 보고에 없는 실제 호스트 값은 미확인으로 표시한다. 패키지 기본 정의는 제품 기준으로 표시하고 개별 호스트의 실효값과 구분한다.

| 항목 | 값의 형식과 범위 | 무엇을 제한하는가 | 현재 센트럴 조회 근거 |
| --- | --- | --- | --- |
| 등록 ID·해지 | 에이전트 ID, 등록 세대 ID, 등록·해지 상태, 시간 | 정책과 업데이트 요청을 적용할 신원을 고정한다. 재등록하면 새 등록 세대가 사용된다. | 중앙 등록 기록과 일치하는 하트비트 |
| 최초 등록 URL·신뢰 CA | 설치 시 승인된 HTTPS 주소와 CA 인증서. 호스트는 일회용 등록 토큰과 로컬에서 만든 키를 사용하며 mTLS는 TLS 1.3 이상 | 에이전트가 연결할 센트럴과 양방향 인증을 제한한다. | 등록 기록과 최근 인증된 통신만 확인. 호스트의 실효 URL·CA 지문·개인키는 미보고 |
| 정책 검증 키 | 등록 시 고정한 Ed25519 공개키와 키 ID | 해당 등록에 전달되는 서명 정책, 제거 승인, 에이전트 업데이트 배포·설치 승인 검증에 사용한다. | 목표·적용 정책 리비전과 수락 결과 조회. 실제 호스트 키 지문은 미보고 |
| 업데이트 발행자 키 | 제품이 신뢰하는 Ed25519 발행자 공개키. manifest에 패키지 SHA-256, 바이트 크기, 패키지 이름·버전·아키텍처를 결합 | 검증한 발행 패키지만 설치하도록 제한한다. 에이전트 패키지와 센트럴 자체 패키지는 각 제품의 서명 문맥을 사용한다. | 업데이트 작업 결과·설치·실행 버전은 별도 업데이트 화면에서 조회. 호스트의 서명 기준·키 지문은 미보고 |
| 원격 업데이트 허용 | 로컬 `updates.enabled` Boolean. 제품 기본 `true` | 해당 호스트가 새로운 센트럴 업데이트 작업을 받아들일지 제한한다. | 별도 업데이트 인벤토리에서 저수준 설정 원문 대신 지원·활성 여부, 확인 시각과 사전검사 사유를 조회 |
| 로컬 프로세스 종료 허용 | 로컬 `response.allow_terminate` Boolean. 기본 `false` | 정책에서 `enforce`를 요청했을 때 호스트가 종료 정책을 받아들일 수 있는지 제한한다. | 현재 등록의 최신 하트비트에서 pidfd가 지원되고 활성 증거가 있으면 허용, 지원 상태가 `available`이면 미허용. 근거가 없거나 오래됐으면 미확인 |

| 서비스 계정·관리 소켓·root 작업자 | systemd 서비스 사용자·그룹, Unix 소켓과 접근 제어, 권한 상승 제한값. 에이전트의 로컬 관리 변경 경로는 root Unix peer를 확인 | 웹 화면, 로컬 관리 요청, RPM 설치 작업자가 가진 운영체제 권한을 분리한다. | 고정 패키지 정의를 문서에서 조회. 각 호스트의 실효 UID·유닛 재정의·파일 소유권은 미보고 |
| SELinux와 실행 경계 | 호스트가 관리하는 `Enforcing`, `Permissive`, `Disabled` 등의 실효 상태 | 패키지 설치를 포함한 운영체제 권한 전환과 서비스 접근을 제한한다. | 실제 모드·실행 도메인은 미보고. 업데이트 실패·성공 기록은 해당 작업 결과로 조회 |
| 외부 웹 접속 경계 | 비루프백 바인딩 허용, 인증 구성, TLS 키, 프록시·방화벽 정책 | 웹패널에 접근할 수 있는 요청과 신뢰 범위를 제한한다. | 실제 노출 주소, TLS 개인키, 인증 설정 원문은 미보고 |

제품 기본 유닛에서 에이전트 웹패널과 센트럴 본체는 전용 비특권 계정으로 동작한다. RPM 설치 작업자는 root로 동작한다. 센트럴의 업데이트 작업은 제품 기본값에서 `0660` Unix 소켓을 통해 전달하며, 작업자만 RPM 설치에 필요한 권한 전환을 허용한다.

변경 권한과 향후 별도 신뢰 관리 서비스는 이 설계의 조회 범위 밖에 둔다. 상세 화면에는 최근 보고와 정책 리비전처럼 확인 가능한 근거를 표시한다. 로컬 종료 허용 보고는 개별 프로세스에 종료 신호를 보냈다는 증거와 구분한다.

## 제품 업데이트와 자동 종료 전환

1. 센트럴과 에이전트의 기능을 함께 릴리스하고 버전이 섞인 상태를 검증한다. 운영 반영은 센트럴을 먼저 업데이트하고, 에이전트 한 대에서 설치·실행 버전, 실제 적용값, 정상 하트비트와 ACK 진행을 확인한 뒤 확대한다. 패키지 업데이트와 대응 모드 변경은 별도 승인으로 운영한다.
2. `observe`에서 정상 서비스 운영과 배포 작업을 관찰한다. `would_block`에서 종료 신호 없이 후보·예외·오탐을 확인한다. 목표 정책과 적용 리비전, 최근 Tetragon 실행·계보 근거, 대응 대상으로 분류되는 실제 규칙을 확인한다. 확장 프로필을 켠 경우 현재 구현의 대응 대상은 0개다.
3. 필요성이 확인되면 대상 서비스와 예외가 명시된 정책을 대표 호스트 한 대에 `enforce`로 적용하고, 실제 적용 리비전과 서비스 영향, 신호 전송 결과를 확인한다. 그룹 확대는 이 결과를 검토한 뒤 결정한다. 복구는 이전 정책 내용을 더 높은 리비전으로 배포한다.
4. 웹 서버의 프로토콜 취약점에는 공급사가 제공하는 패키지 업데이트와 서비스 설정 완화를 적용한다. 현재 에이전트 `enforce`의 범위는 검증된 웹 서비스 자손 셸의 **실행 후 종료 시도**다.

## 검증 기준

- 기존 템플릿·미리보기·저장 API와 구버전 정책 서명을 유지한다. `service_observations` 생략·빈 배열·값이 있는 배열, 기존 무결성 초안 보존, 서비스명이 대소문자만 다를 때의 경고를 각각 검증한다.
- 수신 근거가 있는 센서와 계약만 지원하는 센서를 분리한다. 확장 프로필의 대응 대상 0개, 조회 전용 경계, 정책 만료 시 탐지 유지와 대응 정지를 검증한다. 1,000대에서 미리보기·승인·새 리비전 발행이 끝나는지 확인한다.
- 새 운영 설정 계약은 서명·대상·이전 리비전·만료·중복·잘못된 자료형, 지원하지 않는 필드, 호스트 한도 초과와 수집 충돌을 검사한다. 같은 입력을 재적용해도 작업과 상태가 중복되지 않아야 한다.
- 관측 보존 단축·상속은 격리 DB로 검증한다. 경보 근거와 미확인 전송 자료가 남고, 보고된 만료량과 실측이 일치해야 한다.
- 로컬 웹패널의 허용·차단, 인증된 기존 쿠키와 열린 연결의 다음 조회 차단, 재허용 시 재로그인, 재시작 및 중앙 단절 후 차단 유지, 호스트 차단의 우선순위를 격리 환경에서 시험한다. 패널 차단 중에도 에이전트 수집과 중앙 하트비트·ACK가 진행돼야 한다.
- 수집 설정의 재시작·복구와 중앙 재연결을 시험한다. 호스트 설정을 적용하는 각 구성 요소의 성공을 확인한 뒤 적용 완료를 보고한다.
