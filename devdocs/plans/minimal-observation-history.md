# 센트럴의 최소 관측 이력

## 수신 및 무결성

센트럴은 전체 정규화 페이로드의 호환성·구조화된 권한 근거 검증을 먼저 수행한다. 새 사건을 저장할 때 원문 JSON, 명령 인자, 작업 디렉터리, 조상 스냅샷을 빼고 식별자·프로세스·서비스·관측 결과와 탐지 규칙·점수·요인을 보존한다. 수신 형태의 SHA-256은 로컬 SQLite에 별도로 기록한다. 동일 순번 재수신은 전환 이전의 `deliveries.payload_hash` 또는 스키마 4의 32바이트 영수증으로 확인하며, 다른 순번이나 스풀의 동일 기록 ID도 원본 해시를 비교한다. 만료된 이력은 다이제스트만 남겨 동일 재수신에 ACK를 반환하고 이미 삭제된 페이로드를 되살리지 않는다.

## 만료 대상과 처리량

일반 이벤트의 TTL은 센트럴 최초 수신 시각부터 1시간이다. 탐지가 포함된 이벤트 묶음이나 이미 저장된 독립 탐지가 참조하는 이벤트는 보존한다. 독립 탐지가 만료 후 나중에 도착하면 해당 탐지 자체는 남는다. 감사·등록·정책·업데이트·전송 순번은 이 정리 작업의 대상에서 제외한다. 다이제스트와 전송 순번 이력은 재시도 검증에 쓰이므로 이벤트 본문 TTL의 영향을 받지 않으며 계속 공간을 차지한다.

기존 DB의 묵은 기록은 자동 증가 행 범위의 상한을 기록하고 작은 배치로 분류한다. 분류는 독립 탐지의 참조를 먼저 모두 확보한 뒤 만료를 허용한다. 기존 일반 레코드의 이전 페이로드는 실제 만료까지 남는다. 기존 경보·근거에 포함된 이전 페이로드도 그대로 보존한다. 새로 받은 레코드는 수신 트랜잭션에서 바로 만료 큐에 표시하므로 매번 테이블 전체를 읽지 않는다. 기동 후 분류와 부하로 인한 일시 지연은 수신·정리 우선순위에 따라 발생할 수 있다. 배치마다 쓰기 연결을 양보한다.

## 파일 축소와 운영 복구

삭제한 페이지는 SQLite의 신규 입력에 재사용된다. `auto_vacuum=INCREMENTAL`인 DB에서는 밀린 만료 처리를 마친 뒤 최소 16 MiB의 빈 페이지를 남기고 분당 한 번 최대 256 KiB의 페이지를 반환한다. 반환 시도에는 100ms 기한을 적용한다. WAL을 오래 붙잡는 읽기 스냅샷이 있으면 물리 파일 반환이 늦어질 수 있다.

기존 DB의 auto-vacuum 모드 변경은 서비스를 중지하고 WAL 체크포인트를 확인한 뒤 별도 파일로 수행한다. 남은 공간과 백업을 먼저 확보하고, 원본 연결에서 `PRAGMA auto_vacuum=INCREMENTAL`을 지정해 `VACUUM INTO`로 새 파일을 생성한다. 대상 모드가 `2`인지, `integrity_check`와 등록·ACK·업데이트 상태가 일치하는지 확인한 뒤 소유권·권한을 맞추고 교체한다. 구 데이터 분류 도중 별도의 전체 VACUUM을 하면 SQLite가 암묵적 rowid를 바꿀 수 있으므로 변환된 파일에서 `history_retention_state`의 `last_rowid`를 0, `legacy_max_rowid`를 현재 `max(records.rowid)`로 초기화한 후 시작한다. 초기 배포 전에 변환하면 이 이전 분류 상태가 없다.

DB 스키마 3부터 최소 페이로드와 원문 다이제스트를 사용한다. 스키마 4로 올린 뒤에는 4를 지원하는 빌드가 롤백 대상이다. [수신 영수증 용량 관리](compact-delivery-receipts.md)에 전환 경계와 복구 조건을 정리했다. 구 DB 백업 복원 시 복원점 뒤의 보존·전송 상태도 함께 되돌아간다.
