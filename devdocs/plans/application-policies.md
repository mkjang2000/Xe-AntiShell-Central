# 애플리케이션별 정책 구현

## 완료 조건

- 센트럴에서 기존 정책 템플릿을 검색하고, 호스트 기본 정책에 정확한 시스템 서비스와 고정 정책 버전을 연결한다.
- 같은 에이전트의 nginx 서비스는 모의 대응 또는 자동 종료 정책을 쓸 수 있고, PM2 서비스는 관찰만 하는 정책을 쓸 수 있다. 적용과 권한 조건은 에이전트가 확인한다.
- 정책 전체 목록, 에이전트별 목표와 적용 정책, 배포를 별도 화면 영역에서 조회한다. 배포 전 영향을 검토하고 기존 대상을 명시적으로 확정한다.

## 범위

[정책과 운영 설정 설계](policy-and-agent-configuration.md)의 애플리케이션별 정책에 해당한다. 에이전트 운영 설정과 로컬 웹패널 접근 계약은 별도 작업이다. 현재 등록 인증 방식, 파일 무결성 할당, 업데이트 서명 신뢰의 변경은 이 기능에 포함하지 않는다.

| 저장소 | 변경 범위 |
| --- | --- |
| 공유 프로토콜 | 선택적인 앱 정책 목록, 적용 서명본 다이제스트, 앱 정책으로 평가한 경보의 출처 |
| 에이전트 | 현재 등록의 서명 묶음 검증, 시스템 서비스 귀속 확인, 탐지·대응 선택, 실제 적용 상태 보고 |
| 센트럴 | 템플릿의 고정 버전 매핑과 서버에서 확정한 정책 내용 보존, 지원 확인·미리보기·서명·적용 조회 |
| 정책 화면 | 정책 목록·편집, 에이전트별 적용, 배포의 세 단계. 단위 검색, 서비스 매핑과 대응 모드, 목표·적용 차이와 사유를 먼저 보여 준다. |

## 서명과 적용

- 호스트 기본 정책은 앱 지정이 있으면 관찰 모드여야 한다. 앱은 정확한 시스템 systemd 서비스 하나만 대상으로 하며 파일·TCP 범위와 규칙 제어도 해당 서비스에 속한다. 호스트 전역 권한 탐지, 제거, 모니터링은 호스트 정책이 담당한다.
- 서버는 원본 템플릿의 ID·버전에 결합된 불변 설정을 저장한다. 원본 편집·삭제 이후에도 기존 매핑의 내용을 유지한다. 새 매핑이 현재 버전과 충돌하면 편집자가 새로 확인한다.
- 실행 파일 기준의 셸 실행 예외를 서비스 정책으로 옮길 때 같은 셸의 정확한 서비스 예외를 확인한다. 필요한 서비스 예외가 있으면 저장 단계에서 입력값을 안내한다.
- 호스트 한 대가 적용할 앱 목록을 원자적으로 검증한다. 앱을 지원한다는 현재 등록의 최신 하트비트가 없으면 발행을 거절한다. 호스트에 할당된 이전 유효 정책과 설정은 이 경우 유지된다.
- 직접 서비스 귀속을 검증한 앱을 선택한다. 귀속 불명, 공유 이름, 수집 누락은 기본 관찰로 처리한다. 종료 직전에 실행 대상의 신원과 서비스·정책 세대를 재검증한다. 앱에서 확장 프로필을 켠 경우 기존 규칙대로 탐지만 수행한다.
- 목표 정책과 에이전트가 보고한 적용 정책을 등록 세대와 리비전에 결합한다. 앱 정책이 있는 적용본은 에이전트의 서명본 다이제스트까지 일치해야 확인으로 표시한다. 서명 정책 적용과 서비스별 센서의 실제 수신은 각 근거로 보여 준다.
- 오프라인 정책 비교기는 실행 중인 시스템 서비스 귀속을 확인할 수 없다. 앱 정책이 현행 또는 후보에 있으면 비교 기반 단계 배포를 중단한다. 일반 미리보기에서 에이전트 한 대를 선택해 관찰 또는 모의 대응으로 먼저 적용하고, 현장 보고를 바탕으로 후보 정책을 검토한다.

## 검증

- 기존 서명과 서명 없는 앱 필드의 미사용 동작을 검증하고, 대상이 다른 정책·중복 서비스·다른 서비스의 범위·앱 모드 조작을 거절한다.
- 에이전트가 nginx와 PM2를 따로 선택하고 귀속이 없는 표본은 관찰에 머무는지 확인한다. 모의 대응·만료·로컬 종료 금지 시 실제 신호를 보내지 않는지 확인한다.
- 원본 템플릿의 수정·삭제·동일 이름 재생성, 오래된 호스트의 배포 거절, 같은 등록의 목표·적용 버전 차이와 이전 버전 복구를 시험한다.
- 실제 브라우저에서 정책 검색, 앱 정책 연결, 기본 정책·목표·적용 비교, 모바일과 키보드 접근을 확인한다. 이 과정은 시험 데이터와 격리 센트럴을 사용한다.
