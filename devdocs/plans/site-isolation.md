# 센트럴 사이트 범위

기존 에이전트·등록 토큰·서버 그룹은 기본 사이트에서 시작한다. 계정의 역할 할당을 선택한 사이트와 함께 검사한다. 전체 사이트 작업에는 해당 권한의 전역 할당이 필요하다. 그룹은 한 사이트의 활성 에이전트를 담으며 사이트가 권한 경계를 제공한다.

센트럴에서 사이트 간 이동을 확인할 때 현재 등록 ID와 패키지 작업을 확인한다. 옮긴 에이전트를 기존 사이트 그룹에서 제거하고 이전 하트비트 표시를 비운다. 기록은 수신 시 사이트를 저장해 에이전트가 이동해도 이전 사이트의 이력을 읽을 수 있게 한다. 사이트 ID는 재사용을 피하기 위해 생성·이름 변경만 지원한다.

요청에 `X-XEAS-Site` 헤더를 지정한다. 전역 할당인 계정은 `*`를 사용할 수 있다. 사이트 할당을 받은 계정은 목록에서 접근 가능한 사이트를 선택한다. 사이트 인식 경로는 대상과 사이트를 함께 검증한다. 공유 정책 템플릿은 전역 편집 권한으로 변경한다.

검증은 두 사이트의 에이전트, 정책 대상, 그룹, 이력과 가입 토큰을 사용한다. 다른 사이트 대상·그룹을 직접 제출하거나 이동 전 미리보기로 배포할 때 거부되는지 확인한다.

사이트 권한으로 대상의 에이전트 업데이트 인벤토리와 해당 사이트에서 발행한 배포를 확인·취소한다. 전역에서 발행한 배포와 기존 배포는 전체 사이트 권한이 필요하다. 공유 에이전트 릴리스는 업데이트 조회 권한으로 볼 수 있으며 릴리스 변경과 센트럴 자체 업데이트에는 별도 전역 권한이 필요하다.

역할에는 에이전트 조회, 그룹 관리, 정책 배포, 에이전트 업데이트, 등록·제거 등의 권한을 조합할 수 있다. 사이트가 같은 경우에도 서버 현황, 그룹과 정책 목록은 각 권한으로 결정한다. 전역 정책 편집·시험, 공용 릴리스 관리, 센트럴 자체 업데이트는 전역 권한을 사용한다.

에이전트가 사이트를 이동해도 이미 발행된 업데이트 작업은 원래 사이트에 남는다.

계정이 여러 사이트 역할을 부여받으면 각 사이트에서 유효한 권한을 합산한다. 기본 역할을 제공하며 역할 부여를 수정하고 나면 해당 계정의 옛 전역 역할은 사용되지 않는다. 이전 바이너리에서는 사이트 제한 계정의 로그인이 차단되며 전역 복구 관리자는 유지된다.
