# 정책 영향 비교와 단계 배포

센트럴의 저장된 정책 미리보기에서 선행 호스트를 선택해 비교를 시작한다. 모든 대상에는 원복할 수 있는 기존 서명 정책, 같은 등록의 최신 정상 하트비트와 실제 적용 리비전이 필요하다. 운영자는 호스트별 비교 입력을 내려받아 해당 호스트의 유효 YAML 및 같은 비식별 단일 호스트·부팅 JSONL 표본으로 비교한다.

```
sentinel rules compare --managed-input policy-impact.json --host-config host.yaml --events sample.jsonl > impact-report.json
```

결과 JSON을 선택한 호스트에 등록하면 센트럴이 정책 입력의 SHA-256, 평가 시각, 모든 내장 규칙의 건수와 표본의 일관성을 검사한다. 로컬 설정과 표본은 해시만 보내며 출력에는 규칙별 입력 존재 여부와 경보 추가·감소·변경이 포함된다. UTC 평가 시각을 양쪽에 고정한다. 호스트 YAML과 비교 입력은 인증된 운영자가 선택하므로 결과의 신뢰 범위는 이 입력과 평가한 CLI 버전에 달려 있다. 이 비교는 탐지 판정을 재생하며 자동 대응이나 센서 부착을 실행하지 않는다.

**한 대 선행 배포** 시 비교한 후보를 원래 등록·리비전에 새 리비전으로 서명한다. **그룹 확대**는 선행 호스트가 새 리비전 적용을 정상 하트비트로 보고하고 나머지 대상에 같은 표본의 비교 결과가 있을 때 가능하다. 운영자가 현장 경보·오탐·부하를 검토한 내용을 확인 메모로 남긴다. 각 단계는 담당 계정·대상·단계에 결합된 5분 확인값을 사용한다. 서명 직전 그룹·템플릿·등록·목표와 실제 적용 리비전·지원 여부를 다시 검사한다. 비교 시각 이후 규칙 예외가 만료된 경우 새 비교가 필요하다. 다른 운영자의 변경이나 재등록은 충돌로 처리한다.

**복구**는 앞서 배포한 대상만 선택한다. 각 호스트에 처음 적용됐던 정책 내용과 유효 기간 길이를 보존해 새 발행 시각과 더 높은 리비전으로 재서명한다. 이미 외부에서 바뀐 목표 리비전을 덮어쓰지 않는다. 화면에서 기대·목표·실제 리비전을 대조하고 복구 후에도 적용 보고를 확인한다. 원격 운영 시스템에 새 정책을 실제 배포하려면 기능을 지원하는 센트럴과 에이전트가 필요하다.
